# 现场操作

## 信任边界与唯一大厅

这是私网、现场监督的离线模式，不验证微软账号或 QQ 所有权。只开放 BungeeCord 的 TCP 25565 和只读原版资源包的 TCP 25566；`lobby` 和 `race-a/b/c` 的游戏端口与 RCON 不对外开放。QQ 是签到关联键，不授予管理员权限。不要把 token、RCON 密码或代理控制接口发给参赛者。局域网客户端通过 `http://<主机私网IP>:25566/pack.zip` 下载与服务端 SHA-1 相符的资源包；更改 `.env` 的 `EVENT_BIND` 后用 `scripts/up` 刷新四个世界的地址并重启。网络防火墙须允许私网访问 25565 和 25566。

只有主大厅用于候场和管理员配置。三个比赛世界不提供日常大厅入口；每组仅在最终颁奖时进入自己的原版大厅。最后一图全部组结束后一起进入颁奖，各组颁奖结束后自动回主大厅。中途断开、后端重启或无法完成结果采集时不伪造完成状态。

## 启动与管理员

```sh
./scripts/meet-service serve
./scripts/racectl admin CommentatorA A
./scripts/racectl admin CommentatorB B
```

后两条必须在可信主机控制台执行，目标玩家须在线，且当前没有进行中的 GP。授权只对该次登录会话有效：服务端为此人设置 `xdu_admin`、默认 `xdu_commentary_A/B/C` 标签，并在当前世界临时授予真正的 Minecraft OP；切服时撤销旧世界 OP，离线时撤销所有临时 OP。重连后要由主机重新授权。同名离线账号并不能继承旧会话权限。原版 SprintRacer `ADMIN MENU` 包含与本活动冲突的重启/强制就绪入口，已从主大厅移除；管理员仍可使用原版独立的大奖赛选项设置。管理员开赛后自动进入默认组旁观，不必登记 QQ，不进入人数、名册或成绩；比赛中可用 `/watch A`、`/watch B`、`/watch C`、`/watch lobby` 切组。撤销权限使用 `./scripts/racectl admin Name revoke`，只在 GP 之间执行。离线模式仍依赖现场监督；不要把实际 OP 授予不可信玩家。

## 玩家登记、配置与开赛

1. 玩家通过代理进入主大厅，未绑定 QQ 时持续显示红色“请绑定QQ号／输入 /qq XXX”标题，原版 idle 副标题不再与它争夺显示。私密输入 `/qq 签到QQ号` 后点击聊天中的绿色 `[是]` 或红色 `[不是]`；确认之前不会写入身份，确认之后不能用 `/qq` 覆盖。只接受 5–12 位、不以 0 开头的数字；一个 QQ 只能绑定一个游戏账号。尚未登记的人不能进入比赛服。
2. 报错或登记错号时联系现场管理员。玩家不能自行改绑；代理控制台可在该玩家离线且没有活动 GP 时执行 `xduidentity reset <uuid>`。

开赛前在主机手动运行 `./scripts/meet-service doctor`，核对 `registered_qq_without_signup`。该输出包含私人 QQ，勿发到公共聊天。只有**计划参赛**的名单必须在飞书“用户／QQ号”中有唯一签到记录；未匹配者应先修正签到，或待该账号离线且无 GP 时从代理控制台重置错误绑定。此检查只读云端，不会把玩家姓名或出场情况提前写回飞书。
3. 现场管理员在主大厅进入独立的原版 `Random Track Pool` 编辑区选择赛道池，退出后在 `Grand Prix Setup` 设置轮数、道具、圈数与其他选项；这不是此前被移除的重启/强制就绪 `ADMIN MENU`。发布者链接的 Mario Kart Track Pack 27 条自定义赛道已在主大厅及 A/B/C 四个世界导入。没有固定 3/2/1 赛道规则，也不使用飞书赛程或预分组。循环/无尽 GP 与“最终颁奖后回主大厅”的活动生命周期冲突，须关闭；服务不会偷偷改配置。游戏客户端必须为 Minecraft 26.3 并接受新资源包。
4. 管理员在主大厅输入 `/gpstart`，或在主机执行 `./scripts/racectl start`。服务读取此时在线且已登记的非管理员，随机均分：2–20 人为 A/B，21–51 人为 A/B/C，每组最多 17 人。每次重新抽签，之前的分组不影响下一次。
5. 等待客户端资源包与后端实际入场完成，再启动原版 GP。代理分流与客户端加载分开核对；首次下载新版约 49 MB 资源包允许最多五分钟。超时仍不启动任何组；主机应查网络／资源包并执行 `./scripts/racectl abort --reason '资源包入场超时'`，不能直接重发 `/gpstart`。先完成一图的组进入等待状态；所有启用组结束同一图后，统一倒计时继续。缺失或断开的后端不能被当作完成。

仅加入或开赛不会访问飞书。后台仅处理本地开赛请求、跨服同步、解说权限、回城和归档，不自动更新飞书。

## 成绩 token 与手动上传

颁奖结束后的原始 GP 分数按 QQ、昵称、UUID、实际组别冻结，自动导出到 `exports/`。所有启用组完整归档后，主机日志和管理员游戏消息给出 token。无需猜测文件名：

```sh
./scripts/meet-service tokens
./scripts/racectl status
```

热身赛与正式赛使用同一游戏流程；不上传 token 就不进入飞书积分榜。

要上传时，先在飞书 `比赛控制／当前轮次` 选择目标轮次，然后执行：

```sh
./scripts/meet-service upload --token TOKEN
```

首次上传在任何云端写入前持久化 token → 飞书轮次绑定。改变下拉框不会改变同一 token 的后续重试归属。重复上传不重复计分；另一份完整 token 可以替换同轮的已发布批次，而不是累加重赛成绩。

上传按用户表的 QQ 主字段关联签到记录，并写入游戏昵称。只有此时飞书才得到实际参赛者、当轮组别和成绩。`本轮参赛` 区分“未上传”“已参赛”“未参赛”；未上传不能解释为缺席。未知或重复 QQ 会阻止上传，不按昵称猜人，也不自动新建签到用户。

先写入并读回核对整批成绩，再切换该轮 `已发布批次`。数据异常不替换有效榜单。确认 `最近上传轮次`、token、`最近上传状态=完整` 后再对外发布排名。

若有断线、未完成或身份异常，服务会保留归档/异常记录，但**不会**把这批作为正式已发布成绩；不要仅凭“上传完成”发布榜单。当前没有自动裁定 DNF、补分或排除一人后发布全组的路径。保留 token 和原始文件，现场决定重赛或复核，未经核验不要修改 `已发布批次`。

五轮赛制的积分核对：目前第1—5轮倍率依次为 `1.0、1.1、1.2、1.4、1.6`，第6、7轮仍保留作可选轮次，若实际只举办五轮不要误选。赛中前四次有效已发布成绩直接累加；个人第五次有效成绩起才扣掉最低一轮。因此首轮的“最终总得分”不应显示为零，缺席一轮的人不能再额外丢弃一轮。`总排名`是不扣最低轮的另一个口径；无有效成绩显示空白。完整赛事结束前的“最终排名”仅供暂看，颁奖前复核所有 token 与轮次。

**明早待定的倍率提案，尚未修改飞书**：如果确定只打五轮，可将第4、5轮由 `1.4、1.6` 调为 `1.5、1.8`，前3轮 `1.0、1.1、1.2` 不动。按组内两人、各轮只比较第一名100分与第二名10分、五轮取最佳四轮演算：先赢前三轮的人与后赢两轮的人，现行分别为346与323分；提案为348与353分。后来者有机会反超，前期也仍有价值；代价是末轮胜负权重更大、单场波动增大。第6、7轮目前为 `1.8、2.0`，若举办超过五轮，须重新确认整套倍率，不应机械沿用该五轮提案。今天保留现行值，现场复核后再决定。

## 中断恢复

```sh
./scripts/racectl abort --reason '现场取消本次GP'
```

这是显式取消：先留存不完整归档，再让玩家回主大厅并重置当前运行状态，不签发可计分 token。不要在部分服务器已开始后盲目重新开赛，也不要手改 WAITING、轮次指针、注册文件或成绩归档。

后台重启不会自动重放云端上传。需要重试仍须显式执行 `upload --token`；已绑定的轮次和已写入记录会被复用。

## 明早工作复核

1. 在主机检查 `ipconfig getifaddr en0` 与私有 `.env` 的 `EVENT_BIND` 一致；检查 `docker compose -p xdu-event ps` 六个容器、`./scripts/racectl status` 的 A/B/C 都可读。换了 Wi-Fi 地址要先更新 `.env` 和四个世界资源包 URL 再重启；不能只开放 25565 而忘记 25566。
2. 在主机私密运行 `./scripts/meet-service doctor`，对照 `registered_qq_without_signup`，只处理预计本场参赛者的不匹配 QQ。此命令会打印真实 QQ，不要公开截图；缺席签到用户不需强制到场。确保现场至少四名正式参赛者，以免 A/B 各只有一人、双方都自动获得组内第一名100分；不足四人先当热身赛。
3. 管理员连接 Minecraft Java 26.3 后由主机运行 `./scripts/racectl admin <游戏名> A|B|C`（重连要重新授权）。验证红色 QQ 提示不会与 idle 字幕冲突、确认按钮 `[是]/[不是]`，并实际走进 `Random Track Pool`、试选一条 Mario 赛道再回 `Grand Prix Setup`。确认地图池、局数、道具、圈数，特别是无尽循环已关闭；当前新世界还没有配置 GP 轮数。
4. 先打一场**不上传的热身赛**：只在主大厅 `/gpstart`；看 A/B 或 A/B/C 各完成一图后等齐才进入下一图，最终各自颁奖并回主大厅。用 `./scripts/meet-service tokens` 核对本地 token；热身 token 不要传给飞书。
5. 正赛每次在拿到 token 后明确选择飞书“比赛控制／当前轮次”再手动上传；核对“最近上传轮次”“最近上传状态=完整”及已发布批次。若有人断线导致数据异常，不猜分、不覆盖旧榜，按前述中断流程保留证据并讨论重赛。
6. 在宣布五轮规则前审核上面的倍率提案；如果不希望末轮权重上升，则保持现行值。无论选择哪组，第五轮才扣最低轮；前四轮榜单为累计暂列，第6/7轮只作为重新确认后的备选。
