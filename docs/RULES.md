# Event rules and manual result publication

The live Sprint Racer GP configuration belongs to the administrator in the **single main lobby**. The service neither chooses a fixed map recipe nor creates a seven-round schedule. On each `/gpstart`, it randomly balances the currently registered, online, non-admin players across A/B (2–20) or A/B/C (21–51), with at most 17 per group. Every GP is independent; an unuploaded warmup produces a local archive but no Feishu attendance or score.

The administrator may change the native track pool/sequence, items, laps and saved settings in the main lobby. Other worlds admit only their assigned racers and console-authorized commentators. Native gameplay and award ceremonies remain intact. Each group waits after each track until **all active groups** complete the same track; after the final track each group's native award ceremony concludes before its players return to the main lobby. No incomplete archive receives a publishable token.

The private proxy authenticates Minecraft 26.3 players against the configured Yggdrasil issuer via `authlib-injector`; vanilla race backends remain offline-mode on a private network and cannot be entered directly by participants. `/qq <number>` is a separate self-reported signup key, **not** authentication or proof of QQ ownership. One QQ binds to one proxy-verified UUID until console reset while offline and between GPs; duplicate QQ is rejected. Vanilla gameplay keeps its own offline UUID derived from the authenticated name, recorded separately from the proxy UUID. Administrators are host-authorized for their current authenticated session, forced into spectator mode and excluded from rosters, attendance snapshots and points. `xdu_commentary_A/B/C` picks their default active group; `/watch A|B|C|lobby` changes it without scoring.

Only `./scripts/meet-service upload --token TOKEN` writes the archive to Feishu. The user table's QQ primary field is the business key; the internal Base `record_id` remains a link target. Signup never requires a Minecraft name. Upload refuses unknown or duplicated signup QQ; it writes observed names, actual groups and scores, then verifies readback before switching the selected round's published-batch pointer. The first explicit upload locks token → selected Feishu round before any cloud write. A retry cannot drift when the operator changes the selection. Never upload a warmup token unless deliberately counting it as a formal round.

Native GP points are raw evidence. Feishu computes equal-tie ranking and `(10 + 90 × percentile^1.5) × round multiplier`, where `percentile=(participants−rank)/(participants−1)`; a one-person group gets percentile 1. For a planned five-GP event, `最终总得分` remains the full published cumulative score through a person's first four valid appearances. **Only on the fifth valid appearance** does it subtract that person's single lowest round. Someone who misses one of five rounds keeps all four completed scores; absence does not consume a second deduction. `总排名` ranks `最终总得分` throughout; the existing `最终排名` view uses the same rule and is kept so old view links continue to work. Both are provisional until the event closes. Disconnect/incomplete/unknown observations are not silently treated as valid finishers; an anomalous batch never replaces the last valid leaderboard. Merely registering a QQ or being online is not attendance—only an explicitly published race establishes it. Never interpret an unuploaded round as absence.

Sprint Racer 1.6.14 and the creator-linked Mario Kart Track Pack are third-party content; do not republish either world or resource pack or claim a small local rehearsal establishes production 51-player capacity. The creator's redistribution restrictions remain applicable.
